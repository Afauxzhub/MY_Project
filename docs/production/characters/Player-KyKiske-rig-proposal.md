# Ky Kiske：Biped 混合绑定调查与建议方案

日期：2026-09-21。状态：**调查已完成，用户已批准实施首版；当前进度见 RIG-002**。

实施修订：用户确认去掉 `G_` 前缀、以 `G_Head_Attach`（改名后 `Head_Attach`）驱动头部、整体约 1.8 米。以下读取数据保留为原素材证据；实施与验证见 [RIG-002](../../project/tasks/RIG-002.md)。

本文件针对用户指定的 Ky Kiske 素材，不代表它已被确认为最终 Player 骨架或已经通过游戏资产验收。Player 的已确认约定仍以 [Player.md](Player.md) 为准。调查任务：[RIG-001](../../project/tasks/RIG-001.md)。

## 1. 结论

从实际骨架、蒙皮和控制器结构判断，可以建立以 Biped 为主要动画操作入口的混合绑定，结构可行性的置信度高。建议首版采用 **Biped 身体控制层 + 保留原 G_* 蒙皮骨架 + 附加动画控制器**。

这条路线的准确含义是：动画师用 Bip 制作身体和四肢动作，原骨骼接受驱动并负责变形，面部、头发、披风等使用普通控制器。它不是把 609 根 Bone 全部改成 Biped，也不在首版把 Skin 的全部骨骼引用换成 Bip。

若另行要求最终 Skin 直接绑定 Bip 主骨、只保留附加 Bone，则属于更深入的替换方案，需要替换 Skin 引用、重挂子骨并逐项对比绑定矩阵和变形。当前素材的加权结构使其风险和工作量明显更高。

## 3. 决定方案的关键事实

### 主链完整，变形骨与主链分离

躯干链为 `G_body_root → G_pelvis → G_waist → G_stomach → G_chest → G_neck`。左右上臂、前臂、手、大腿、小腿、脚、趾链均存在。

`G_pelvis`、`G_waist`、`G_stomach`、`G_chest`、`G_neck`、`G_uparm_L/R`、`G_lowarm_L/R`、`G_thigh_L/R`、`G_calf_L/R`、`G_foot_L/R` 本身没有有效顶点权重；网格大量依靠其子级变形骨。肩部 `G_shoulder_L/R`、`G_clavicle_L/R`、手、拳、手指、脚趾等则有权重。

因此，简单把主骨替换成 Bip 或只替换 Skin 骨骼列表，均不能自动获得等价变形。保留现有 Skin 引用及原骨架更容易建立可比较的基线。

### 原来的自动修形不能假定仍然存在

场景中有 `G_uparmup/mid/low_*`、`G_lowarmup/mid/low_*`、`G_shldrhalf_*`、`G_knee_*`、`G_ankle_half_*` 等骨，但此次控制器树中没有发现对应的程序驱动。名称能提示用途，不能证明其正确驱动比例。

需要逐项建立并验证前臂扭转分配、肩部和肘膝半角跟随、必要的手动修正。不能承诺恢复游戏原始的全部风格化修形逻辑。

### 尺寸与头部中间骨需要专门处理

系统单位为 `meters`、SystemScale 为 1；显示单位为厘米。网格世界包围盒 Z 约为 -0.019857 至 73.595535，即高度约 **73.615 米**。这个尺寸不适合直接进入本项目。数值可能涉及导入时的单位解释，但本次没有确定其历史原因，也没有擅自选定最终身高。

`G_Head_Attach` 和 `G_Head_def` 位于头部高度约 64.5669，而二者之间的 `G_head_root` 世界位置在原点附近。它不是可直接拿来放置 Bip Head 的头部关节；需要保留原层级偏移，并按实际颈头枢轴建立映射。

## 4. 建议实施顺序

1. **建立工作副本和基线。** 原 `1.max` 保留；另存候选绑定文件。记录节点身份、完整 Skin 权重、初始变换、参考网格、单位和朝向。先确定目标身高，再对整套角色做一致的单位/尺寸校准，不单独缩骨、Reset XForm 或用 Unity 任意缩放掩盖问题。
2. **拟合 Biped。** 在 Figure Mode 按实际关节位置建立骨盆、3 节脊柱、1 节颈、头、标准双臂双腿、每手 5 指且每指 3 节、每脚 1 条趾链的候选配置。具体关节位置优先，原肩部多段结构及拳骨保留；指名 a–e 与 Bip Finger 的对应按实际空间位置确认。
3. **建立身体驱动。** Bip 驱动对应原主骨，保留初始位置/旋转偏移。使用单向、可检查、可烘焙的驱动，避免约束循环和父级双重变换。首个检查点为接线前后参考姿势顶点一致。
4. **补齐变形和附加控制。** 原变形骨保留权重；为扭转、半角和关节修形添加经过姿态测试的驱动与修正入口。面部先做眼睛朝向、眨眼、嘴和下颌等基础控制；头发、披风、衣领、腰带以分组 FK 和局部修正为首版，不默认制作自动布料动力学。保留 `G_grip_L/R` 等挂点。
5. **整理制作操作。** 分开 Biped、身体修正、面部、头发、衣物、原变形骨和网格层；提供选择集、参考姿势恢复和基础手势。隐藏/冻结不应直接操作的骨骼，避免动画师从 609 根骨里找控制器。完整动画保存在 `.max`；BIP 动作复用不能代替附加控制器动画的保存。
6. **验证发布骨架和 Root Motion。** 按项目约定新增独立 `Root`，与 Biped COM 分开。候选组织是 Root 下的 Biped 控制分支与原蒙皮骨架分支，网格变换另行检查。身体驱动按世界结果计算并正确还原局部空间，避免 Root 位移重复计算。最终只发布约定的变形骨架与所需挂点，控制器不进入游戏骨架。

主要映射候选：

| 原骨链/用途 | 动画入口或处理 |
| --- | --- |
| `G_pelvis` | Bip Pelvis；Bip COM 保持独立职责 |

## 5. 现有导出工具的边界

本次源码核对发现 `rm_indoor_backend_baselayer.ms` 通过 `Bone_Skin_Bip001 Pelvis` 判断既有独立蒙皮骨架分支；`rm_proxy_fbx_export.ms` 和 `adv_fbx_export_v25.ms` 再决定是否排除 Biped 分支。原素材的 `G_*` 结构不满足这个特定识别条件。

因此不能承诺接上 Bip 后现有按钮就能自动只导出 G_* 骨架。正式实施需检查实际发布入口，并为明确选定的导出分支建立兼容规则、测试 Root 位移只应用一次；不为触发已有判断而随意把原骨改名。该适配尚未实施，Unity 设置亦未改动。

## 6. 后续验收

- 参考姿势：接入驱动前后逐顶点比较；尺寸校准后的比较使用同一尺度基线；Skin 骨引用、权重总量与拓扑保持预期。
- 身体：下蹲、抬腿、脚掌锁定、抬臂、肩部大角度、肘膝深弯、前臂扭转、握拳和转头；检查塌陷、拉伸及翻转。
- 附加部分：眼球与眨眼、张嘴、头发和披风链；检查跟随及手动修正是否可控。没有运动测试前，静态权重正常不等于蒙皮合格。
- 动画操作：Biped IK/FK、脚步接触、关键帧与层使用、保存并重新打开，确认完整控制关系和动画保留。
- 导出：短动作逐帧对比 Max 与 FBX，再导入 Unity 验证尺寸、方向、姿态、Root 轨迹、附加骨曲线及重复发布引用稳定；真实链路归入 ANIM-001。
- 首版保留高骨数以验证质量；若未来要削减 609 根骨，应另做骨骼预算和变形误差评估，不能直接删除无权重骨，因为它们可能是有权重骨的祖先。

本次只完成文件读取和结构分析，没有制作 Biped，没有进行变形动作测试，也没有进行 Unity / FBX 验收。
