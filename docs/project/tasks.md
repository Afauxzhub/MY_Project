## 状态定义

| 状态 | 含义 |
| --- | --- |
| `Backlog` | 已记录，尚未满足开始条件或未排到当前里程碑 |
| `Ready` | 依赖明确，可以开始 |
| `In Progress` | 当前正在实施 |
| `Awaiting Runtime Validation` | 静态工作完成，仍需 Unity、3ds Max、动画或游戏运行验收 |
| `Blocked` | 无法继续，必须记录阻塞原因和解除条件 |
| `Deferred` | 有意暂缓，必须记录恢复条件 |
| `Done` | 验收条件和所需验证全部完成 |

同一时刻原则上只有一个主要实现任务处于 `In Progress`。状态不代表主观完成度，以任务卡的验收证据为准。

## 新任务登记规则

- ID 使用稳定前缀和递增编号，例如 `UNITY-002`、`MAX-001`、`BUG-001`。
- 标题描述可观察结果，不使用“继续开发”“完善系统”等无限范围表述。
- 新任务必须写依赖和完成条件；较复杂任务从 `tasks/task-template.md` 复制任务卡。
- 任务关闭时填写验证证据和相关提交，不删除历史任务。
