# 无连线动作工作台：制作与交接指南

更新：2026-10-16。实现入口：`Tools > MY Project > Animation > Motion Workbench (No Wires)`。任务状态以 [MOVE-011](../project/tasks/MOVE-011.md) 和 [任务索引](../project/tasks.md) 为准；本页不是另一份待办清单。

## 清晰的落地目标

**程序位移模式下，一套无需 Animator 连线的角色移动制作流程：模型/模板 → 独立动作库 → 填槽/绑定审核 → 编辑衔接 → Play 观察与调参 → 显式保存 → 导出缺项。**

支持的语义包括双套姿态、走跑冲刺、八向靶向移动、方向起步、左右停步、加减速、弧线/急弧、移动 90° 转向/180° 折返、原地转身，以及起跳/上升/顶点/下落/落地。缺动画时程序仍可测试，但回退姿势不是动画质量通过。

这一范围内补已有语义的动画或换同类型角色，不要求重建 Animator 或改播放代码。增加攀爬、游泳、受击规则、独立新动作语义，仍属于程序扩展，不是往任意命名槽里拖动画就能自动实现。Root Motion 新路径见下方第 7 节（MOVE-013）；真实 Max 发布、动态锁脚/脚滑、生产战斗系统和最终美术调优仍单独验收。

## 1. 使用当前角色

打开独立 `AceNoWiresLab` 测试场景；选择同目录 `AceMotionLibrary`，打开工作台。参考资源都在被 Git 忽略的 `Client/Assets/LocalAnimationLab` 内，不要将其依赖复制到正式提交目录。

工作台编辑的是草稿：

- **保存差异**：验证配置并写动作库和移动参数；支持 Undo。源资产被其他操作修改时拒绝覆盖。
- **应用到 Play**：只复制到本次运行角色；退出 Play 后失效。要求场景中恰好一个角色使用当前源库。
- **丢弃草稿**：重新加载源库；会询问是否放弃未保存修改。
- 预览模型、裁剪、速度、配方不会改写原 `.anim`/FBX。不要修改 `Generated/AnimationClips` 内的源曲线来存游戏配置。
- 旧库先点 **补齐新版本动作槽**，新增原地转身等缺槽只写草稿，已有引用/参数保留。不会在导入后偷偷改旧库。

### Play 键位

| 输入 | 用途 |
| --- | --- |
| WASD / Ctrl / Shift | 相机相对移动 / 走 / 冲刺 |
| 右键鼠标 | 镜头 |
| F2 | 测试强制切换两套姿态；不是生产切武器流程 |
| V | 请求收放动作；需相应动作与权限，缺资源不能据此验收 |
| Tab | 靶向开关 |
| Q / E | 无移动输入时请求左/右转身；靶向时由锁定目标决定面向 |
| C | 跳跃；默认键可在移动参数修改，Space 不是跳跃 |
| J / K / Space / G / L | 旧灰盒轻击 / 重击 / 闪避 / 防御 / 技能，仍受权限门控制 |
| H / P | 模拟受击 / 暂停灰盒动作 |

## 2. 新动画怎么加

先按 [资产工作流](../production/asset-workflow.md) 发布个人动画：DCC 源文件在 `ArtSource/`，动画 FBX 在 `Client/Assets/Art/Animations`，提取 `.anim` 在 `Client/Assets/Generated/AnimationClips`。保留原文件名与 `.meta`，重复发布后复核绑定和效果；不要把游戏资源塞进 reusable package。

少量动画直接在“动作库”操作：

1. 选择姿态：`Sheathed` = 放松/主城，`Drawn` = 战斗准备；在当前参考角色上不表示真实持刀。
2. 从“编辑槽”选择目标。例如 `Sheathed / Any / Walk / Any / Any`。槽位决定用途，Clip 文件名不驱动运行状态。
3. 拖动画到 `Clip`，开启 `Enabled`。点击“检查模型绑定覆盖”。路径一致只是必要条件，不自动证明骨架比例/姿势正确。
4. 配入出点、速度和适用条件；右侧预览衔接。真实观察后点“标为已人工审核”。临时借用动作选“标为临时替代”。
5. 应用到 Play 检查；满意后显式“保存差异”。

字段说明：

| 字段 | 用途 / 注意 |
| --- | --- |
| Mode | `Any` 明确共享；`Free` / `Targeting` 只在对应模式使用。具体模式覆盖共享槽 |
| Gait / Direction | 步态、方向条件。起步方向是初始运动方向相对角色面向；八向持续移动使用专用 Strafe 槽 |
| In Point / Out Point | 原动画归一化区间 0～1；右侧双柄条也可拖。不是源文件剪切 |
| Speed / Phase Offset | 播放速率；循环相位偏移用于对齐左右脚，不能代替修正动作本身 |
| Stage Seconds | 一次性阶段时长覆盖；0 继承移动参数。对起步、停步、转身、落地使用；跳跃由 Motor/腾空阶段驱动，加减速由速度变化驱动 |
| Minimum / Maximum Speed | 动画适用速度，m/s；一次性阶段用进入时的选择速度，循环用当前速度。未命中会回退并显示缺项 |
| Minimum / Maximum Angle | 绝对角度 0～180；用于过滤，不会旋转源动画或自动镜像 |
| Reference Speed + Match Playback To Speed | 填此动作原始速度并显式启用，按当前速度调整步频；倍率受库的上下限限制。未知保持关闭 |
| Contact Authored + Left / Right Contact | 脚接触曲线，横轴是**原 Clip 归一化时间**，值 0～1；混合后的已知支撑用于选左右停步。未知或双脚不明确时显示半周期估计；不锁脚、不做 IK |
| Match Name | 批量候选的精确名称；留空按槽建议名称。只影响导入提议，不影响运行 |
| Optional | 标记额外细化，不把每个步态覆盖都误算为必需动画 |

同一组姿态/模式/槽/步态/方向，只允许一个启用条目，重复配置会拒绝保存。新增变体时先设选择条件，再启用。可清空引用或禁用；不会删除原资源。

### 批量填槽

进入“批量填槽”，选择动画目录、本批姿态和可选文件名前缀，点“扫描候选”。例如 `Hero_Run`，前缀填 `Hero_`，可匹配 Run 槽；`Start_Left` 对应左起步。大小写和分隔符会规范化，但不会模糊猜测 `RunEnd` 是左停步还是右停步。特殊命名可在槽的 `Match Name` 写清。

扫描不改草稿。逐行勾选，重名时明确选一个，检查绑定；已有引用默认不可覆盖。点击“确认勾选项 → 写入草稿”才生效；整批预检失败时不写任何一项。填入后仍为 Pending review，不会自动当作动作质量通过。

## 3. 怎么调融合和衔接

右侧选“上一动画 / 下一动画”，指定匹配步态、方向和源/目标模式。默认显示与运行相同选择规则命中的配方。勾选“试播所选覆盖”是人工强制试播，明确不代表运行会命中。

模板只读：点“复制命中模板为角色覆盖后编辑”。角色覆盖优先于公共模板；同层先比 Priority，再比条件数量，同排名冲突回退安全默认并报警。

- 黄色竖线：融合时长 `Blend Seconds`；`Weight`：目标权重曲线，0 起、1 结束。
- 上下裁剪条：两个 Clip 的独立入出点。帧步进是固定 30 fps 的预览步长，不会改变源采样帧率。
- `Preserve Cycle Phase`：保持循环相位；关闭后用 `Target Phase` 指定入口。
- `Interrupt After`：当前融合允许切换的进度门；空中、落地、模式变化和已获准战斗动作不会被普通移动配方卡住。
- `Bridge`：可选专门过渡动作、桥接时长和退出融合。运行不依赖 Timeline。
- 转身的 `Turn Interrupt` 是阶段中断比例，与配方的融合中断门不同。

预览复用 Playables 混合核心，但不模拟碰撞、全部运动阶段、脚步 IK 或战斗判定；应在 Play 中检查实际命中。当前是姿势快照淡入淡出，不是惯性化融合算法。

预览选择跟随动作槽的稳定 ID：填入其他空槽、移除其他引用或重排，不会把正在预览的上一/下一动作换掉。如果所选槽本身被清空或禁用，预览会回退到仍可播放的条目，应核对右侧名称。

## 4. 换角色

菜单 `Tools > MY Project > Animation > New Character Lab (No Wires)`：

1. 选择新模型 Prefab/FBX；可以先留空，用胶囊测试机制。
2. 可选旧库作配置模板，默认**不复制旧角色动画**；要复用相同骨架动画时明确勾选，并重新审核绑定。
3. 填不存在的 `Assets/...` 目录。已有目录会拒绝；参考模型必须创建在 `Assets/LocalAnimationLab/...`。
4. 创建 `Motions.asset`、独立移动参数/配方子资产、灰盒 `CombatProfile.asset` 和 `Test.unity`。不生成 Animator Controller、不覆盖旧资产、不改 Build Settings，也不保存/关闭当前场景。
5. 手动打开新 `Test.unity`，确保只运行一个测试场景；给新库填动作即可。当前向导使用标准 1.8m 胶囊，其他体型需调整 CharacterController 与镜头。

旧角色的工作台未保存草稿不会被新建向导加载/丢弃。库里的模型字段主要用于预览和绑定审核；更换运行场景模型应使用新角色向导，不会随“应用到 Play”自动替换网格。

| 起跳 / 上升 / 顶点 / 下落 / 落地 | 5 项缺，可按实际动作拆段复用 | 同左 |

基础空缺合计放松 31、战斗准备 39。可选细化是双套各 3 步态 × 8 个靶向方向（48）及两套 IdleVariation（2）；放松待机变体已赋。自由/靶向专用起停和切模式桥接按最终效果需求增加，不强制每种组合一条独立文件。

资源报告入口在“运行 / 覆盖 → 导出当前草稿资源需求”，同时生成 JSON/TXT，包含选择条件、建议名称、基础/可选、空缺/禁用/临时代用/待审核/审核过期等状态。请保存到 Assets 外的本地目录；报告可能含本地参考资产路径，不提交公司资源清单。

同页的“刷新资源审核表”生成当前草稿快照，可以分页、仅看未赋基础槽，并点“定位”跳回动作槽；修改草稿或重新发布后需要刷新表。上方 Play 运行诊断是实时的（界面最多约 10 次/秒刷新，不影响动画自身更新）。

## 6. 代码完成与效果完成的边界

代码目标是让上述常见移动语义可配置、可预览、可测试；不是承诺补一批任意动画就自然获得最终动作质量。最终仍要做脚相位、动作速度、转向角度、落地时机、融合曲线及镜头观察的人工验收。动态锁脚和滑步修正保留在 MOVE-010，不能提前用 IK 掩盖基础动作缺失。

战斗编辑器与动作权限仍保留现有灰盒范围；支付资源、命中结果、伤害/硬直、AI 等生产功能受战斗任务约束，本轮不宣称全部战斗代码完成。后续实际剩余功能统一记录到项目任务索引，不在本页再造待办。

### 程序复验入口

`Tools > MY Project > Animation` 下可运行：

- `Validate Authoring Workflow (no source writes)`：候选/重复名/绑定/覆盖保护、资源报告、模式/接触/速度元数据、原地转身与非法输入，使用合成数据。
- `Validate No-Wires Core (no scene save)`：真实 PlayableGraph 采样/混合、独立重播时钟、匹配与快速中断。
- `Run Editor Logic Checks (no scene save)`：保留的动作/预览/静态 IK 旧回归，不意味着动态 IK 已开启。
- `Run No-Wires Play Sweep > 30 / 60 / 120 fps`：只用于 clean 的 LocalAnimationLab 场景、恰好一个新播放器；自动进入/退出 Play 并还原帧率、垂直同步、后台运行和 timeScale。回放在实际动画帧上推进，不依赖编辑器重绘节奏。

回放报告在 `Client/Library/NoWiresValidation/play-*.json`；帧率是本次实际运行采样，不是性能保证。地形/连续输入机制另用下面的 MOVE-012 入口；第二套真实骨架及真人操作观感仍须另验。

2026-10-16 前台续验已完成：最终运行版三组实际约 30.00 / 59.93 / 119.83 fps，均无失败；48 项工具 Editor、123 项播放器 Editor、17 项旧 Editor 和 60 项纯逻辑通过。真实裁剪/融合拖柄、Undo/Redo、保存重载、候选确认、缺项表翻页定位、JSON/TXT 导出和应用到 Play 已验证。MOVE-011 因此关闭；这不是全部动画资源、最终画面或脚步质量通过。

### 地形与完整输入矩阵（MOVE-012）

在非 Play、未修改的隔离测试场景中，选 `Tools > MY Project > Animation > Run Terrain and Input Matrix > 30 / 60 / 120 fps`。场景需恰好一个新播放器、AnimationLabInput 和 AnimationLabCamera。一次约 3.6 分钟，运行期间不要手动改场景或输入；可停止 Play 中断，报告会记为失败，不伪造完成。

- 自动创建临时坡道、平台和地板，退出 Play 后消失；不保存场景。
- 24 个真实 CharacterController 碰撞用例：三档模拟步长 × 15/30/44/60° × 上下坡；允许坡保持接地，60° 上坡阻挡。模拟步长不是实际渲染 fps。
- 237 个连续输入步骤：双套 × 自由/靶向 × 走跑冲刺 × 八方向（96 段），24 个有向换挡组合及准备段、快速镜头跨 ±180°/俯仰边界、反向松键、跳跃/落地、目标停用、坡面跳、落边无输入/反向/锁定、战斗暂停/恢复和受击返回。
- 回放提交 LabInputFrame，和键盘共用动作入口；每帧在 Motor 完成后检查状态、实际位移、权重、节点数及权限。它不是物理键鼠或手柄设备验收。
- 报告保存在 `Client/Library/NoWiresValidation/matrix-*.json`，包含逐段阶段和缺 Clip 记录。三档结果与修复记录见 [MOVE-012](../project/tasks/MOVE-012.md)。报告、截图和参考角色仍留本地。

Motor Inspector 的 Ground Snap Distance 默认 0.35m，仅控制从接地状态沿可走坡面向下的根碰撞校正；不等于脚 IK，不会在空中持续吸地。动态锁脚、滑步、脚底贴坡和骨盆修正仍留到 MOVE-010。

## 7. Root Motion：新播放器的配置入口

本节对应 MOVE-013，不需要 Animator 连线。原库默认仍使用程序位移，不会自动改成根运动。

### 移动动作槽

1. 在动作工作台选择角色库，确认“预览模型 / 绑定”和 Clip。模型必须与运行角色使用同一 Avatar/骨架；换模型后重新提取。
2. 选中动作槽，点击 **提取所选动画根轨迹（仅草稿）**。数据写入草稿，原动画不变；支持 Undo。若提示没有导入根轨迹，先核对 FBX 的 Root/Motion 节点及 Bake Into Pose 设置，不要随意填写髋骨名。
3. 展开 `Root Motion`：`Enabled` 启用 XZ 根位移，`Rotation` 使用动画根转向，`Scale` 调整位移距离。移动槽不启用 `Vertical`，走坡、落边和跳跃继续使用 Motor 重力。
4. 查看根轨迹俯视图、时长、净位移/转角；按原流程修改裁剪、相位、速度与融合。图中显示源轨迹，不模拟碰撞或混合后的实际路径。
5. “应用到 Play”测试副本；确认后“保存差异”。源 Clip 或模型重新导入后，过期轨迹会阻止保存/应用及相应场景 Play/build，重新提取即可。

`Rotation` 关闭时沿程序朝向使用根步幅；开启时由动画增量控制对应权重的 Y 轴转角，不再叠加同权重的程序转身。胶囊保持直立，不用根 Pitch/Roll 翻转角色。碰撞会截断根位移，阻挡解除后不会追赶之前没走完的距离。非等比/负缩放角色应先统一尺度并独立验收；此轮验证覆盖正常正向、等比缩放。

### 战斗动作

在 Combat Action Editor 选择动作和预览模型，点击“提取动作根轨迹（不改源动画）”，再配置：

| 字段 | 含义 |
| --- | --- |
| Movement = RootMotion | 让当前动作使用根轨迹；Stationary 立即停止位移，Procedural 使用已有输入权限 |
| Root Motion Scale | 战斗动作的距离倍率；不使用嵌套 Settings 中的 Scale |
| Apply Root Rotation | 战斗动作是否采用根转角；不使用嵌套 Settings 中的 Rotation |
| Root Motion / Vertical | 动作显式接管 Y；不叠加相同权重的重力，结束后恢复重力 |
| Animation Time | 仍只映射动画/根轨迹时间，Hitbox/Cancel 等玩法窗口时间不变 |

动作编辑器保持既有显式 Save/Undo 流程，Play 中锁定源动作编辑。未提取的 RootMotion 动作会明确保持位移并显示错误，不会偷换成程序移动。播放方式不新增空中攻击、受击脱离或支付权限。

### 诊断与复验

- “运行 / 覆盖”显示 `Motor / extracted Root Motion`、根位移/转角请求、XZ/Y/转向权重，以及 Motor 碰撞后的实际速度。
- `Tools > MY Project > Animation > Validate Root Motion Core (no source writes)` 验证原生提取、裁剪/跨圈、时间映射、混合、缩放、缺项与序列化。
- `Run Root Motion Sweep > 30 / 60 / 120 fps` 在干净隔离场景运行。合成 Clip、配置副本与碰撞装置只存在 Play，报告留在 `Client/Library/NoWiresValidation/root-*.json`。
- 转场仍是姿势快照淡出，快照没有继续推进的根速度；融合会改变实际过渡段距离，需要调融合/倍率。这不是 Motion Warping、惯性化或动态锁脚。
- 真实角色步幅、骨架兼容和美术表现，以及首条 Max→FBX→Unity 发布，仍需要独立验收。当前本地 Ace 原库未自动启用根运动。

## 8. 已有参考动画的独立 Root Motion 测试

MOVE-014 为现有参考角色另建了本地 Root Motion 场景；原无连线场景继续保留程序位移基线。新场景不需要 Animator Controller，也不需要等待新资产。场景、配置、轨迹、模型和贴图只留在本机，不随代码推送。

### 打开现成副本

1. 在 Project 的 `Assets/LocalAnimationLab` 中找到本轮 Root Motion 专用目录，双击 `RootMotionLab.unity`。不要在公司工程打开或覆盖原参考场景。
2. 进入 Play。`WASD` 移动，`Shift` 冲刺，松键停步；`F2` 强制切换放松/战斗准备套。这是测试切套，不是假装已制作拔收武器。
3. 按 `J` 进轻攻击，在允许连段的窗口继续 `J`；`Space` 闪避，`H` 模拟受击，`P` 暂停/恢复。持续按移动方向，可观察动作结束后回到移动。
4. HUD 的 Motion 应显示 `Motor / extracted Root Motion`；同时看期望速度、Motor 实际速度和 Missing。起步/攻击的速度本来就随原轨迹变化，不应期望每帧等于跑速。
5. 打开动作工作台，将该目录的 `Motions.asset` 作为编辑对象；战斗动作编辑器使用同目录 `Combat.asset` 中的动作子资产。不要误改原程序位移库。仍按“草稿 → 应用到 Play → 明确保存”的流程调融合、裁剪与倍率。

双套已有 Idle/Start/Run 和可用 Stop 使用真实轨迹；放松套还有原生弧线、冲刺。战斗准备套的冲刺/弧线缺资源时回退 Run，真实 Walk、八向靶向、90°/180°、跳跃等仍以资源表为准。缺靶向等动画而回退 Idle 时，借的是姿势，程序移动仍可运行，不会被零位移待机锁死；画面可能站姿滑移，不算补齐对应动作。新副本关闭脚 IK，动态锁脚与滑步最后处理。

### 为另一个现有本地角色创建副本

退出 Play，打开**干净且已保存、只有一个新播放器角色**的 LocalAnimationLab 场景，选择：

`Tools > MY Project > Animation > Create Root Motion Lab Copy`

文件框中选已有的 LocalAnimationLab 父目录，输入一个**新的名称**。工具自动创建同名新目录，其中放 `RootMotionLab.unity`、`Motions.asset`、`Combat.asset`，随后打开新场景；目录已存在会拒绝，不覆盖。所有已赋 Clip 需具备可提取的原生根数据，否则先报告缺项；没有分配 Clip 的槽仍留空。

工具会独立复制两套移动参数、配方、动作和连段引用，按提取步幅填写循环参考速度；动作时长与窗口/事件时点仅在**本地战斗副本**中等比适配原片段长度，以观察完整动作。它不是正式战斗平衡配置，也不修改原 Clip。原始素材更新后仍要重新提取轨迹。

### 重跑现有动画衔接检查

在新场景非 Play、clean 状态下运行：

`Tools > MY Project > Animation > Run Authored Root Motion Sweep > 30 / 60 / 120 fps`

每档约 88 秒，55 段真实 PlayerLoop 输入，使用场景中已有动画和根轨迹，不替换为合成动画。要求双套基础移动以及现有灰盒动作 ID `L1`–`L4`、`Dodge`、`LightHit` 已配置；这不是任意角色一键质量认证。

检查双套起停/弧线/冲刺、切套、移动进攻击/四段连击/闪避/受击/回移动、暂停与碰撞，另验缺靶向动画时仍能移动并返回真实自由移动。60 档会保存代表性转场多时点画面；报告和截图在 `Client/Library/NoWiresValidation`，不会上传。目标 fps 不等于性能保证，报告保留实际平均与最长帧时间。最终融合审美、完整资源、真人输入手感和动态脚部质量仍分别验收。
